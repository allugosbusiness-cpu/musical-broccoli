# Render.com Deployment Guide for PulseTrack Backend

## Overview
This guide explains how to deploy the PulseTrack Django backend to Render.com, which is more stable and reliable than Railway for Django applications.

## Step-by-Step Deployment

### 1. Create Render Account
- Go to [render.com](https://render.com)
- Sign up with GitHub (recommended for easy deployment)
- Create a new account or log in

### 2. Connect GitHub Repository
- In Render dashboard, click **New +**
- Select **Web Service**
- Connect your GitHub account (if not already connected)
- Select the `Fleet Management` repository
- Make sure branch is set to **main** (or your deployment branch)

### 3. Service Configuration
The `render.yaml` file in the root directory already contains all necessary configuration:

```yaml
services:
  - type: web
    name: pulsetrack-backend
    runtime: python310
    buildCommand: pip install -r requirements.txt && python manage.py collectstatic --noinput && python manage.py migrate
    startCommand: gunicorn Logistics.wsgi:application --bind 0.0.0.0:$PORT --workers 4
```

**Render will automatically:**
- Read `render.yaml`
- Create the PostgreSQL database
- Set up the web service
- Configure environment variables

### 4. Environment Variables on Render

Render Dashboard → Your Service → Environment:

```
DEBUG=false
SECRET_KEY=<generate-random-key>
ALLOWED_HOSTS=*.render.com,*.vercel.app,pulsetrack-frontend-henna.vercel.app
CORS_ALLOWED_ORIGINS=https://pulsetrack-frontend-henna.vercel.app
DATABASE_URL=<auto-generated by Render from PostgreSQL service>
PYTHON_VERSION=3.10.0
```

**Important:** The `DATABASE_URL` will be automatically provided by Render's PostgreSQL service defined in render.yaml.

### 5. Deploy

**Option A: Automatic Deployment**
- After connecting GitHub and configuring render.yaml, pushes to main branch trigger automatic deploys
- Go to **Deploys** tab to watch progress

**Option B: Manual Deploy**
```bash
# Simply push to GitHub
git add -A
git commit -m "Prepare for Render.com deployment"
git push origin main
```

### 6. Verify Deployment

Once deployed, your backend URL will be:
```
https://pulsetrack-backend.render.com
```

**Test the connection:**
```bash
curl https://pulsetrack-backend.render.com/api/v1/health/
```

### 7. Update Frontend Configuration

In `client/Frontend/src/config/apiConfig.js`, update for Render:

```javascript
const getApiBaseUrl = () => {
  if (isProduction) {
    return 'https://pulsetrack-backend.render.com/api/v1';
  }
  // ... development config
};
```

Then rebuild and redeploy frontend:
```bash
cd client/Frontend
npm run build
npx vercel --prod --yes
```

## Database Management

### Access PostgreSQL Console
1. In Render dashboard, go to **pulsetrack-db** service
2. Click **Connect**
3. Use the connection string to connect via `psql` or other tools

### Database Backups
Render automatically creates daily backups. Restore via Render dashboard if needed.

## Monitoring & Logs

### View Logs
- Render Dashboard → Your Service → **Logs** tab
- Shows build and runtime logs

### Environment Issues
Check logs for:
- `ERROR: could not connect to database`
- `ModuleNotFoundError`
- `CSRF verification failed`

### Common Issues & Solutions

| Issue | Solution |
|-------|----------|
| 500 errors after deploy | Check **Logs** tab for database connection or import errors |
| DATABASE_URL missing | Verify PostgreSQL service is running in render.yaml and DATABASE_URL is linked |
| Static files missing | `python manage.py collectstatic` runs in buildCommand; verify staticfiles_dirs in settings |
| CORS errors | Update CORS_ALLOWED_ORIGINS and CSRF_TRUSTED_ORIGINS in settings.py |
| Slow startup | Render free tier has limited resources; upgrade to paid for better performance |

## Scaling & Performance

- **Free Tier**: 0.5 CPU, 512 MB RAM (spins down after 15 min inactivity)
- **Paid ($7-12/month)**: 1 CPU, 512 MB-1 GB RAM (always on)

For production, upgrade to paid plan to avoid cold starts.

## Rollback to Previous Deployment

1. Render Dashboard → **Deploys** tab
2. Find previous successful deployment
3. Click **Redeploy** button

## Comparison: Railway vs Render

| Feature | Railway | Render |
|---------|---------|--------|
| Django Support | Good | Excellent |
| Reliability | Moderate | High |
| Build Logs | Minimal | Detailed |
| Cold Starts | Yes | Yes (free tier) |
| Price | $5+/month | $7+/month |
| Setup Difficulty | Medium | Easy |
| Documentation | Good | Excellent |

## Security Checklist

- [ ] DEBUG=false in production environment
- [ ] SECRET_KEY is strong and random
- [ ] ALLOWED_HOSTS configured correctly
- [ ] CORS_ALLOWED_ORIGINS limited to Vercel frontend
- [ ] CSRF_TRUSTED_ORIGINS includes Render and Vercel domains
- [ ] Database URL uses strong password
- [ ] No API keys hardcoded in settings.py
